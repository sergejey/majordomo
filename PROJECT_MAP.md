> **Note**: Consult AGENTS.md before starting any task. Never index or modify the `3rdparty/` directory.

## 1. Overview & Technology Stack

**MajorDoMo** (Major Domestic Module) is an open-source, multi-protocol smart home automation platform designed for Windows and Linux environments.

- **Backend**: PHP (PHP 7.x - 8.x compatibility, OOP domain model combined with procedural framework utilities).
- **Database**: MySQL / MariaDB (custom DB layer with query wrappers and schema management in `db_terminal.sql`).
- **Caching & Realtime**: Optional Redis support (`lib/redis_helper.class.php`), custom WebSocket server (`lib/websockets/` and `cycle_websockets.php`), and long-polling / Ajax endpoints.
- **Background Execution**: Multi-process CLI worker architecture (`cycle.php` orchestrating multiple background cycles via `lib/threads.php`).
- **Templating**: Custom jTemplates / parser engine (`lib/parser.class.php`, `lib/jTemplate.class.php`) supporting tags like `<#LANG_...#>`, `[#if ...#]`, `[#begin ...#]`, `[#include ...#]`.
- **Localization**: Multi-language system loaded from `languages/` (default fallback `languages/default.php`, user language defined in settings or session).

## 3. Core Architecture & Execution Flows

### 3.1 Web Request Flow (Frontend & Admin)

1. **Bootstrapping**:
   - `config.php` defines DB credentials (`DB_HOST`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`), paths (`ROOT`, `DIR_MODULES`, `DIR_TEMPLATES`), and environment switches (`DEBUG_MODE`).
   - `lib/loader.php` initializes DB connection `$db = new mysql(...)` and loads core framework classes (`perfmonitor`, `general`, `module`, `errors`, `objects`, `common`, `caching`, `sqlFunctions`).
   - `load_settings.php` loads all key-value records from the `settings` table into PHP `SETTINGS_*` constants and applies timezones and language settings.
2. **Controller Routing**:
   - `index.php` instantiates `application` (`modules/application.class.php`), checks session, resolves the requested view/action, runs the active module, and executes post-processors (`lib/utils/postprocess_*.inc.php`).
   - `admin.php` instantiates `panel` (`modules/panel.class.php`), verifies admin authentication, loads `control_modules`, and renders module configuration tabs.
   - `nf.php` catches friendly URLs (e.g., `/panel/event/1.html`) via web server rewrite rules and maps them to module actions.

### 3.2 REST API Flow (`api.php`)

`api.php` provides JSON endpoints for external integration, third-party apps, and mobile frontends:
- `/api/devices[/{id}[/{links|schedule}]]`: CRUD for Simple Devices, their linked behaviors, and schedules.
- `/api/rooms[/{id}]`: Rooms and location management.
- `/api/data/{property_or_object}`: Retrieve or batch-update property values.
- `/api/history/{property}`: Query historical time-series data for a property.
- `/api/method/{object.method}`: Invoke an object method with JSON/GET parameters.
- `/api/script/{script_name}`: Execute a stored automation script.
- `/api/events/{event_name}`: Trigger registered system events.
- `/api/messages`: Query or publish chat / shoutbox messages.
- `/api/module/{module_name}`: Delegate requests directly to a specific module API handler.

### 3.3 Background Daemons Flow (`cycle.php`)

1. Executed via CLI: `php cycle.php`.
2. Connects to database and automatically verifies and repairs tables (`CHECK TABLE`, `REPAIR TABLE`).
3. Re-checks module installation states and clears outdated cache data.
4. Spawns and supervises worker threads from `scripts/cycle_*.php` using `Threads` class (`lib/threads.php`).
5. Supervision loop:
   - Polls pipe statuses and checks process liveness.
   - Restarts crashed or terminated cycles according to backoff rules.
   - Listens for cycle control flags (e.g., `<CycleName>Control` global property).

## 4. Major Subsystems & Module Catalog

MajorDoMo modules reside in `modules/<module_name>/`. Modules extend `module` (`lib/module.class.php`) and implement `run()`, `getParams()`, `saveParams()`, and optional `admin()` / `api()` methods.

### 4.1 Object-Oriented Smart Home Core

| Module | Path | Primary Tables | Responsibility |
|---|---|---|---|
| **classes** | `modules/classes` | `classes`, `methods`, `properties` | Manages class hierarchies, inheritance, and default method/property schemas. |
| **objects** | `modules/objects` | `objects`, `pvalues`, `properties` | Manages object instances, descriptions, location bindings, and property values. |
| **properties** | `modules/properties` | `properties`, `pvalues` | Defines properties, history storage rules, and linked modules. |
| **methods** | `modules/methods` | `methods` | PHP code / script logic attached to classes or specific objects. |
| **pvalues** | `modules/pvalues` | `pvalues`, `phistory` | Manages actual property value records and linkage to time-series history. |
| **history** | `modules/history` | `phistory`, `phistory_queue` | Time-series history viewer and maintenance for object properties. |
| **linkedobject** | `modules/linkedobject`| `properties`, `pvalues` | Helper interface for selecting and binding objects/properties to widgets and devices. |

### 4.2 Simple Devices Architecture (`modules/devices`)

The Simple Devices framework provides a standardized abstraction layer over raw objects:
- **Base Classes**: `SDevices`, `SControllers` (switches), `SDimmers`, `SRGB`, `SThermostats`, `SAirConditioners`, `SSensors`, `SMotions`, `SOpenClose`, `SLeak`, `SSmoke`, `SCounters`, `SCameras`, `SMedias`, `STVs`, `SVacuums`, `SButtons`, `SGroups`.
- **Linked Devices (`devices_linked`)**: Automatic rules linking devices together (e.g., motion sensor -> switch on light, door sensor -> turn off AC).
- **Scheduler Points (`devices_scheduler_points`)**: Time-based and condition-based setpoints.
- **Homebridge / Apple HomeKit**: Built-in sync helpers (`homebridgeSync.inc.php`, `processHomebridgeMQTT.inc.php`).

## 5. Background Cycles Reference (`scripts/`)

Each cycle runs as a separate background process started by `cycle.php`:

| Script | Cycle Name | Responsibility |
|---|---|---|
| `scripts/cycle_main.php` | `cycle_main` | 1-minute system tick; runs `ThisComputer.StartUp` on boot, checks daily/hourly events, triggers periodic maintenance. |
| `scripts/cycle_scheduler.php` | `cycle_scheduler` | Executes scheduled jobs (`jobs` table) and timed timeouts set by `setTimeOut()`. |
| `scripts/cycle_execs.php` | `cycle_execs` | Async command execution queue (`safe_execs` table) preventing UI blocking. |
| `scripts/cycle_phistory.php` | `cycle_phistory` | Flushes buffered property history data (`phistory_queue` table) to `phistory` tables. |
| `scripts/cycle_ping.php` | `cycle_ping` | Periodic ping checking for hosts registered in `pinghosts`. |
| `scripts/cycle_states.php` | `cycle_states` | Monitors device state changes and triggers state update methods. |
| `scripts/cycle_connect.php` | `cycle_connect` | Maintains cloud connection with MajorDoMo Connect servers. |
| `scripts/cycle_websockets.php` | `cycle_websockets` | Native PHP WebSocket server pushing property updates and shouts to browser clients in real time. |
| `scripts/cycle_wscache.php` | `cycle_wscache` | Buffers and syncs WebSocket message queue (`cached_ws` table). |
| `scripts/periodical_db_save.php` | `cycle_db_save` | Periodic database backup and dump to `database_backup/`. |
| `scripts/snmp_trap_daemon.php` | `snmp_trap` | Daemon listening for incoming SNMP traps from network hardware. |

## 7. Essential Core Functions & Helper APIs

When developing or patching code, **always reuse existing core functions** rather than reinventing them.

### 7.1 Database Functions (`lib/sqlFunctions.class.php`)
- `SQLSelect($sql)`: Executes SELECT query and returns array of associative rows.
- `SQLSelectOne($sql)`: Returns single associative row (or empty array).
- `SQLInsert($table, &$record)`: Inserts associative record into table; returns inserted ID and sets `$record['ID']`.
- `SQLUpdate($table, &$record, $key_field = 'ID')`: Updates record matching key field.
- `SQLExec($sql)`: Executes raw query (INSERT, UPDATE, DELETE, ALTER, etc.).
- `DBSafe($string)` / `DbSafe1($string)`: Escapes string for SQL queries.

### 7.2 OOP & Property Functions (`lib/objects.class.php`)
- `getGlobal('Object.Property')`: Retrieves property value for an object (checks memory/cache, then DB).
- `setGlobal('Object.Property', $value, $no_linked = 0, $source = '')`: Updates property value, handles linked modules, pushes to WebSockets, and writes history if configured.
- `callMethod('Object.Method', $params = array())`: Invokes object method (or inherited class method).
- `callMethodSafe('Object.Method', $params = array())`: Invokes object method safely in a background process.
- `getObject('ObjectName')`: Returns instantiated object instance.
- `addClass($className, $parentClass = '')`: Creates a new object class.
- `addClassObject($className, $objectName)`: Instantiates a new object under a class.

### 7.3 Timers, Scripts & Scheduling (`lib/common.class.php`)
- `setTimeOut($title, $commands, $timeout_seconds)`: Sets or overrides a named timeout timer.
- `clearTimeOut($title)`: Cancels an active named timeout.
- `timeOutExists($title)`: Checks if a named timeout is currently pending.
- `addScheduledJob($title, $commands, $datetime, $expire = 1800)`: Schedules command execution at a specific datetime.
- `clearScheduledJob($title)` / `deleteScheduledJob($id)`: Removes scheduled job.
- `runScript($id_or_name, $params = array())`: Executes stored script synchronously.
- `runScriptSafe($id_or_name, $params = array())`: Executes stored script in background subprocess.

### 7.4 Speech, Audio & Notifications (`lib/messages.class.php`, `lib/common.class.php`)
- `say($phrase, $level = 0, $member_id = 0, $source = '')`: Broadcasts speech announcement across terminals matching minimum importance level.
- `sayTo($phrase, $level = 0, $destination = '')`: Sends speech announcement to a specific terminal or user.
- `sayReply($phrase, $level = 0, $replyto = '')`: Replies to voice command on originating terminal.
- `ask($prompt, $target = '')`: Prompts user with question and awaits voice/text response.
- `playSound($filename, $exclusive = 0, $priority = 0)`: Plays sound file on system audio device.

### 7.5 Event Hooks & Subscriptions (`lib/hooks.inc.php`, `lib/events.class.php`)
- `subscribeToEvent($module_name, $event_name, $filter = '', $priority = 0)`: Subscribes module to system event.
- `unsubscribeFromEvent($module_name, $event_name)`: Removes event subscription.
- `processSubscriptionsSafe($event_name, $details = array())`: Safely dispatches event notification to all subscribed modules.
- `registerEvent($eventName, $details = '', $expire_in = 0)`: Logs system event occurrence into `events` table.

### 7.6 Logging, Diagnostics & Utilities (`lib/general.class.php`)
- `DebMes($message, $logCategory = 'debug')`: Appends log line to `cms/debmes/` daily log files (`<date>_<category>.log`).
- `dprint($data, $stop = 1)`: Dumps formatted variable contents and optionally halts execution for debugging.
- `gr($var_name, $type = 'trim')`: Global request parameter getter (reads from `$_REQUEST` / `$_GET` / `$_POST` with type casting: `'int'`, `'trim'`, etc.).
- `redirect($url)`: Performs HTTP redirect.
- `outHash($sourceArray, &$targetHash)`: Copies array values matching template hash placeholders.
- `getURL($url, $cache = 0)`: HTTP GET request with optional caching.
- `postURLBackground($url, $params)`: Async HTTP POST request.

## 8. Agent Working Rules Checklist

When executing tasks in this codebase:
1. **Targeted Inspections Only**: Check this map first, locate the responsible module in `modules/` or core file in `lib/`, and inspect only relevant files.
2. **Never Touch `3rdparty/`**: Do not read, search, or index files in `3rdparty/`.
3. **Preserve Compatibility**: Maintain PHP 7.x/8.x compatibility and do not break the database schema expectations in `db_terminal.sql`.
4. **Follow Conventions**: Use `gr()` for input sanitization, `SQLSelect*()` for database queries, `DebMes()` for debug logging, and `getGlobal()` / `setGlobal()` for object property management.
5. **Post-Task Verification**: Run syntax checks (`php -l`) on modified PHP files and update `PROJECT_MAP.md` only when module responsibilities or system architecture materially change.
